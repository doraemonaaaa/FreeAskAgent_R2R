# Subgoal 指令跟随 Benchmark 实验报告

日期:2026-09-19。数据集:R2R-CE val_unseen 分层 200-set(`integrations/v3/eval_sets/val_unseen_200.txt`),子指令边界来自 FGR2R。被测系统三个,方法代码均未改动(CA-Nav、AwareVLN 只加了轨迹导出):

| 系统 | 类型 | 配置 |
|---|---|---|
| v19(FreeAskAgent) | 零样本,JoyAI 观察 + Qwen3-VL-8B 决策 | 6 视角预览、无 navmesh、opening look-around |
| CA-Nav | 零样本,GPT-4 离线解析 + 价值图 | 上游 exp1_nogate |
| AwareVLN | R2R 上 SFT 的 8B | 官方 FP16 checkpoint |

结果文件:`results/{v19,canav,awarevln}/`(每个变体的 runner 格式 trace 与 metrics json),汇总表 `results/COMPARISON.md`。代码与用法见 `benchmark/README.md`,设计与修订见 `docs/subgoal_benchmark_design.md`。

## 1. 精简后的协议

每个系统:ORIG 一次(复用)+ FLIP 一次(主指标)+ GOAL-ONLY 一次(过拟合诊断)。随机性系统另跑一次 ORIG 作噪声底线,所有变体共用。SWAP / DROP 为第一版指标,保留作附录,新系统不需要跑。

## 2. 新 benchmark:FLIP-k(主实验)

在 k ≥ 2、参考路径按该词方向转 ≥ 45°、反方向 2 m 可通行的句子里反转左/右,其余一字不改。47 集(CA-Nav 可映射 42 集)。指标:到达第 k−1 段边界后 5 m 内的最大转角判左 / 右 / 直行(参考路径 agent 一致率 1.00)。

| 指标 | v19 | v19 噪声底线 | CA-Nav | AwareVLN |
|---|---|---|---|---|
| 原指令下转向与原词一致 | 0.593 (n=27) | 0.593 | 0.452 (n=31) | 0.784 (n=37) |
| 反转后与反转词一致 | 0.500 (n=28) | 0.231 (n=26) | 0.324 (n=34) | 0.341 (n=41) |
| 反转后仍按原词转 | 0.429 | | 0.441 | 0.366 |
| 成对:换了方向 | 0.500 (n=24) | 0.333 (n=24) | 0.065 (n=31) | 0.457 (n=35) |
| 成对:原来对、反转后也对 | 0.250 | 0.042 | 0.032 | 0.314 |
| SR 原 / 反转 | 0.213 / 0.149 | 0.213 / 0.128 | 0.190 / 0.190 | 0.681 / 0.553 |

噪声底线 = v19 同配置再跑一次 ORIG 与第一次 ORIG 之间的差异。

**分析**

- **CA-Nav 对方向词是盲的。** 42 集里 23 集轨迹逐点相同,SR 一个不变。代码只在阶段首个约束是"方向约束"时使用这个词(42 段里 25 段满足),且只是价值图 1.5 倍扇区加权,不足以改变路径。
- **AwareVLN 的高一致率不是靠读这个词。** 原指令下 0.78,但反转后只有 34% 按新词转、37% 仍按旧词、其余直行;SR 掉 13 个点。单换一个词它既不跟随也不坚持,而是乱了。结合 SWAP(见第 4 节)它整条换指令能跟,说明它依赖的是 landmark 和终点物体,不是方向词本身。
- **v19 有微弱但高于噪声的响应。** 反转后 50% 按新词转(噪声 23%),25% 两次都对(噪声 4%)。配对样本只有 24,置信区间宽。SR 的变化(0.213 → 0.149)在两次 ORIG 的波动(0.213 → 0.128)以内,不能归因于反转。
- **三个系统没有一个达到可靠的句子级方向跟随**(参考 agent 为 1.0)。

## 3. 新 benchmark:GOAL-ONLY(过拟合诊断)

只保留最后一段子指令(含停止条件;最后一段是光秃秃的 "Stop." 时多保留前一段),删掉全部过程句。174 集。看去掉路线描述后 SR、路径贴合度和中间边界到达率掉多少:掉得少说明 SR 不是靠过程句得来的,再看中间边界到达率区分"靠布局先验走了应走的路"和"靠搜索找到终点"。

全部 174 集(v19 单 JoyAI 副本,16:08 到 22:50):

| 指标(原 → 只给目标) | v19 | CA-Nav | AwareVLN |
|---|---|---|---|
| SR | 0.253 → 0.161 | 0.241 → 0.184 | 0.624 → 0.353 |
| 相对下降 | 36% | 24% | 43% |
| SGCR-eff | 0.386 → 0.297 | 0.410 → 0.328 | 0.746 → 0.508 |
| 中间边界到达率 | 0.548 → 0.409 | 0.657 → 0.577 | 0.821 → 0.613 |
| nDTW | 0.354 → 0.390 | 0.162 → 0.168 | 0.653 → 0.481 |
| 路程 m | 19.4 → 11.3 | 28.3 → 25.8 | 13.2 → 11.9 |
| 步数 | 147 → 84 | 218 → 204 | 113 → 123 |
| 原来成功的保住比例 | 0.409 (18/44) | 0.286 (12/42) | 0.444 (48/108) |
| 原来失败、只给目标反而成功 | 10 (7.7%) | 20 (15.2%) | 13 (20.0%) |

**分析**

- **下降幅度本身分不出"依赖详细指令"的程度**:三个系统相对下降都在 24% 到 43%,保住原有成功的比例都在 0.29 到 0.44。差别在机制,要看路径指标:
  - AwareVLN 去掉过程句后 nDTW 从 0.65 掉到 0.48、中间边界到达率从 0.82 掉到 0.61、步数反而变多,是真的在读路线描述,去掉就退化成搜索。这不是背路线的表现。
  - CA-Nav 路径几乎不变(nDTW 0.16 → 0.17,路程 28 → 26 m),它本来就只用终点物体类别搜索;SR 的下降来自解析里少了部分 landmark。
  - v19 路程从 19 m 缩到 11 m、步数减半,nDTW 反而略升:planner 只切出一个 subgoal,judge 很快判完成然后 STOP。它对指令的响应仍然走"subgoal 数量 → STOP 时机"这条路,与 DROP 一致。
- **"SR 掉得少 = 有探索到达能力"只对 CA-Nav 成立一半**:它确实靠探索,但代价是 200 多步走 26 m;对 v19 不成立,它是提前停,只在短 episode 上碰巧对。
- **三个系统并没有收敛到同一批 episode**。GOAL-ONLY 成功集的重叠(Jaccard):v19–CA-Nav 0.11、v19–AwareVLN 0.20、CA-Nav–AwareVLN 0.15;174 集里三个都成功的只有 3 集,任一成功的 91 集。SR 相近是巧合,解的是不同的题。ORIG 下的重叠也只有 0.13 到 0.25。
- **GOAL-ONLY 的成功偏向短而直的 episode,三个系统都有,CA-Nav 最明显**:成功集里起终点测地距离 ≤ 6 m 的比例,v19 18%、CA-Nav 28%、AwareVLN 20%,全集 14%;测地/直线比 1.12 / 1.19 / 1.15,全集 1.25;三个都失败的 83 集是最难的一组(≤ 6 m 只占 10%,比 1.34,K 3.45)。也就是说只给目标时的成功有"episode 简单"的成分,但不是全部:AwareVLN 61 个成功里测地距离均值 8.6 m,与全集 8.9 m 相差不大。
- **完整指令有时反而有害**:AwareVLN 有 13 集(原失败集的 20%)只给目标反而成功,CA-Nav 20 集(15%),v19 10 集(8%)。对 AwareVLN 这可能是过程句里的 landmark 把它带偏。

## 4. 旧 benchmark:SWAP / DROP-k(附录)

SWAP = 换成同场景另一条 trajectory 的整条指令;DROP-k = 删掉第 k 句(k < K)。全部 200 / 176 集。

| 指标 | v19 | CA-Nav | AwareVLN | 参考 agent / 无指令 oracle |
|---|---|---|---|---|
| SR ORIG | 0.255 | 0.255 | 0.625 | |
| SGCR / SGCR-eff | 0.471 / 0.376 | 0.604 / 0.422 | 0.794 / 0.748 | 0.99 / 0.99 |
| SWAP:SR | 0.120 | 0.115 | 0.265 | |
| SWAP:ISens-SGCR | 0.054 | 0.100 | 0.228 | 0.57 / 0.00 |
| SWAP:PathAttrib(同起点 donor) | 0.586 | 0.547 | 0.758 | 1.00 / 0.01 |
| SWAP:SGCR'(按换入指令边界) | 0.510 | 0.600 | 0.750 | 0.99 / 0.41 |
| DROP:SR 原 → 删句 | 0.250 → 0.170 | 0.246 → 0.263 | 0.625 → 0.460 | |
| DROP:Skip | 0.691 | 0.833 | 0.785 | 0.06 / 0.97 |
| DROP:LocFail(随机 0.30) | 0.268 | 0.158 | 0.195 | 0.94 / 0.03 |
| DROP:PrefixKeep | 0.855 | 0.981 | 0.955 | 0.99 / 0.99 |

**分析**

- **SWAP**:AwareVLN 是唯一路径明显跟着换入指令走的系统(同起点归属率 0.76,按换入指令边界的完成率 0.75,接近它原指令下的 0.79)。v19 和 CA-Nav 的路径归属率都在 0.55 附近,与随机无差;两者 SR 掉一半只是因为终点物体变了。
- **DROP**:三个系统的 Skip 都在 0.7 到 0.83,LocFail 都不超过随机,包括 AwareVLN。这说明 DROP 被房屋布局混淆:被删的那段多数只有一条路可走,任何 agent 都会"照样走到"。这是第一版设计的缺陷,因此 DROP 降为附录,主实验改为 FLIP。
- **SGCR 的虚高**:CA-Nav 走满 250 步、路程 28 m,顺路按序撞上边界,SGCR 0.60;加路程预算的 SGCR-eff 后降到 0.42,与 v19 的差距从 13 个点缩到 5 个点。
- **v19 相比 CA-Nav 的唯一明确优势是路径效率**:同 SR 下路程短一半,SPL 0.195 对 0.110,nDTW 0.366 对 0.172。

## 5. 总体结论

1. 在 R2R 分布内,AwareVLN 的指令跟随是真实的(SWAP 跟得上、GOAL-ONLY 去掉过程句后路径贴合度大幅下降),不是背路线;但它对单个方向词不敏感(FLIP)。它真机上的不泛化更可能来自场景和指令风格的分布差异,这需要换分布的实验(自建场景、非 R2R 措辞)才能检验,本 benchmark 目前测不到。
2. v19 的指令响应主要体现在 STOP 时机(subgoal 数量),句子级跟随只有微弱信号;路径效率是它相对零样本同类的优势。"FreeAskAgent 泛化性更好"的假设没有被本次实验证实,也没有被测到。
3. CA-Nav 对过程句和方向词基本不读,靠终点类别搜索加不早停拿到 SR。
4. 对 v19 的开发建议:以 FLIP 的"反转后与反转词一致"和"两次都对"作为句子级 grounding 的目标指标;judge 判断第 k 段完成时应对着第 k 句的 landmark 和动作验证,而不是按节奏推进。
5. 统计上,47 集的 FLIP 区间很宽,两次 ORIG 之间 SR 就能差 8 个点;要下更强的结论需要把 FLIP 集扩到全量 val_unseen(按同规则约 400 多集)。

## 6. 数据与实现注意事项

- FGR2R 覆盖 200-set 全部;R2R-CE 的 start + reference_path + goal 与 FGR2R viewpoint 一一对应(connectivity 图核对)。
- FLIP 只用 k ≥ 2:k=1 的起始朝向在 R2R-CE v1-2(v19 用)和 v1-3(CA-Nav、AwareVLN 用)之间不一致。
- CA-Nav 运行时不读指令原文,只读 GPT-4 离线解析;SWAP 用 donor 的解析,DROP / FLIP / GOAL-ONLY 是从原解析里删或改对应子指令,没有重新调 GPT-4。
- v19 的 SWAP / DROP / FLIP / GOAL-ONLY 用单个 JoyAI 副本跑,只影响速度。
