# 200-set 结果:CA-Nav、v19(FreeAskAgent)、AwareVLN

跑于 2026-09-17 到 19。CA-Nav = 上游 exp1_nogate;v19 = 6 视角预览、无 navmesh、opening look-around(ring6_200 配置);AwareVLN = 官方 FP16 checkpoint。方法代码均未改动(CA-Nav、AwareVLN 只加了轨迹导出)。

## 主实验:FLIP-k(反转一句里的左/右,47 集,CA-Nav 可映射 42 集)

选段规则见 `benchmark/build_flip.py`:k ≥ 2、句中只含一个左/右词、参考路径在该段按该词方向转 ≥ 45°、反方向 2 m 处可通行。指标:到达第 k−1 段边界后 5 m 内的最大转角,判左 / 右 / 直行(参考路径 agent 一致率 1.00)。

| 指标 | v19 | v19 噪声底线(ORIG vs 第二次 ORIG) | CA-Nav | AwareVLN |
|---|---|---|---|---|
| 到达锚点(原 / 反转) | 0.617 / 0.617 | 0.617 / 0.596 | 0.738 / 0.810 | 0.830 / 0.894 |
| 原指令下转向与原词一致 | 0.593 (n=27) | 0.593 | 0.452 (n=31) | 0.784 (n=37) |
| 反转后与反转词一致 | 0.500 (n=28) | 0.231 (n=26) | 0.324 (n=34) | 0.341 (n=41) |
| 反转后仍按原词转 | 0.429 | | 0.441 | 0.366 |
| 成对:换了方向 | 0.500 (n=24) | 0.333 (n=24) | 0.065 (n=31) | 0.457 (n=35) |
| 成对:原来对、反转后也对 | 0.250 | 0.042 | 0.032 | 0.314 |
| SR 原 / 反转 | 0.213 / 0.149 | 0.213 / 0.128 | 0.190 / 0.190 | 0.681 / 0.553 |

读法:
- **CA-Nav** 对左右词是盲的:42 集里 23 集轨迹逐点相同,SR 不变。代码里只有阶段首个约束是方向约束时才用这个词(42 段里 25 段),且只是价值图 1.5 倍扇区加权。
- **AwareVLN** 原指令下一致率 0.78,反转后只有 34% 按新词转、37% 仍按旧词、其余直行:高一致率不是靠读这个词,单换一个方向词它就乱了。SR 掉 13 个点。
- **v19** 反转后 50% 按新词转、25% 两次都对,对应噪声底线 23% 与 4%,信号存在但 n ≈ 25,区间宽。SR 差异(0.213 → 0.149)在两次 ORIG 之间的波动(0.213 → 0.128)以内,不能算作反转的效果。
- 三个系统里没有一个在句子级方向词上达到"可靠跟随"(参考 agent 为 1.0)。


指标定义见 `docs/subgoal_benchmark_design.md`,结果文件在 `results/canav/` 与 `results/v19/`。

### 读法

1. 两个系统 ORIG 的 SR 完全相同(0.255),但路径完全不同:CA-Nav 走 28 m / 214 步,v19 走 18.5 m / 142 步;v19 的 SPL、nDTW 高一倍。
2. SGCR 上 CA-Nav 高 13 个点,SGCR-eff 后只剩 5 个点且区间重叠:CA-Nav 多出来的"按序经过边界"主要是走满 250 步顺路撞上的。
3. 换整条指令(SWAP):两者 SR 都掉一半,说明终点判定都跟着指令走;但 PathAttrib 都是 0.54,与随机 0.5 无差,ISens 都很小。两者的轨迹形状都不由指令决定,指令主要影响"最后找什么停"。
4. 删一句(DROP-k):CA-Nav 的 SR 一点不变,Skip 0.83,LocFail 0.16 低于随机。它完全不依赖单句。v19 的 SR 从 0.250 掉到 0.170,Skip 0.69,LocFail 0.27 接近随机,PrefixKeep 0.855:v19 对删句有反应,但反应方式是整体变差(前缀也受影响,路程从 18.5 m 缩到 14.4 m,步数 142 → 109,即更早 STOP),不是"恰好在那一段失败"。
5. AwareVLN 是三者里唯一在 SWAP 下路径明显跟着指令变的(同起点 donor 归属率 0.76,按换入指令边界完成率 0.75):它在仿真里确实按指令走,不是背路径;真机上的不泛化更可能来自场景分布而非指令分布。但 DROP 下它的 Skip 仍 0.79、LocFail 低于随机,说明 DROP 被布局混淆(被删段多数只有一条路),DROP 只作辅助。
6. 与自检的两个假 agent 相比,两个真实系统在 ISens / PathAttrib / LocFail 上都更接近最短路 oracle 而不是参考 agent。benchmark 把"SR 0.25 但不是逐句执行"这件事在两个系统上都量化出来了,原始指标里只有 SWAP 的 SR 下降能看出一点,DROP 在 CA-Nav 上完全不可见。

## 注意

- CA-Nav 的 DROP 输入是从原 GPT-4 解析里删掉重叠子指令得到的,没有重新解析;5 条无法映射的剔除。
- v19 的 SWAP/DROP 用单个 JoyAI 副本跑,只影响速度。
- 三个系统的方法代码都没有改;CA-Nav、AwareVLN 只加了轨迹导出。
- v19 在 47 集上两次 ORIG 的 SR 相差 8 个点(0.213 / 0.128),这种规模的 SR 差异不能归因于变体。
