## 2. preview 基准（150 个沿参考路径的决策点，8 视角，真值 = 测地路径方向）
"转弯点" = 路线方向偏离正前方 >30° 的点。
| 方法 | 总体最近视角正确 | 转弯点 |
|---|---|---|
| 永远正前方 | 42% | 0% |
| VLM 5 视角选（8B / 32B） | 39% / 37% | 30% / 31%（含直走点） |
| VLM 8 视角 / 8 视角+深度事实 / 全景 / 8 图找地标 / 方向词先验 | 19–41% | 11–17%（≈随机 12.5%） |
| SigLIP 检索阶段名词（err≤45°） | 31% | 36%（房间类名词 47%，n=17） |
| **SAM3 检测阶段名词 → 框中心方位角（err≤30°，检测到的点）** | 34% | **34%，top-3 任一 54%** |

### 2.1 VLM 各输入形式的逐项数字（同一 150 个决策点，87 个转弯点；脚本 `bench/score_preview_vlm_views.py`、`bench/score_preview_vlm_variants.py`，原始输出 `outputs/experiments/preview_bench3/raw/`）
| 输入形式 | 8B 总体 / 转弯点 | 32B 总体 / 转弯点 | 每点耗时 |
|---|---|---|---|
| 永远正前方（基线） | 42% / 0% | 42% / 0% | – |
| 5 视角选一（随机 20%） | 39% / 30% | 37% / 31% | 0.8 / 1.1 s |
| 8 视角选一（随机 12.5%） | 32% / 21% | 29% / 18% | 1.0 / 1.4 s |
| 8 视角 + 深度/可通行事实 | 33% / 22% | 31% / 22% | 1.0 / 1.4 s |
| 全景拼接图选方位 | 19% / 14% | 27% / 14% | 0.7 / 0.8 s |
| 8 帧找阶段地标（locate8） | 33% / 14% | 23% / 11% | 0.8 / 1.1 s |
| 仅指令方向词先验（无图） | 41% / 17% | 39% / 15% | 0.25 / 0.37 s |
| 先验 + locate8 | 33% / 17% | 23% / 14% | 0.8 / 1.1 s |

要点：(a) 转弯点上所有形式都在随机水平附近，最好的 5 视角（30%）也低于"人看全景"的水平；(b) 信息更多的形式（8 视角、全景、8 帧历史）反而比 5 视角差，说明限制在模型读图能力而非输入信息量；(c) 8B 与 32B 无系统差异；(d) 不看图只读方向词的先验（41%）和看图的差不多，即图像几乎没贡献。

SAM3 在 43% 的点有检测（"走向 X"类阶段 59%），每视角 ~90 ms。第一版"最近视角"打分会把跨两个 45° 视角的正确检测判错。

结论：VLM 无论何种形式都无法从图像选方向；SAM3 是唯一在转弯点给出可用方向信号的工具，且 top-3 + 消歧比单步选择更可行。

## 3. SAM3 接进主循环（`skiils/grounding.py`，`VLN_GROUNDER=sam3`）
每步用阶段名词短语检测当前帧；未检测到时请求 preview（每阶段一次、之后每 12 步一次）并用 SAM3 扫 5 视角；检测到的地标替换 Captioner 的 u/v，多检测时问 VLM 消歧。40 集 A/B：

| 配置 | SR | SPL | 进度 | 到达最后子目标 | 早停(对) | 每步 |
|---|---|---|---|---|---|---|
| som_on3（8B，无 SAM3） | 0.07 | 0.04 | −0.31 | 0.47 | 12 (3) | 1.5 s |
| **sam3_8b** | 0.07 | 0.05 | −0.16 | 0.47 | 12 (3) | 3.2 s |
| qwen32b_on（32B，无 SAM3） | 0.10 | 0.06 | −0.05 | 0.35 | 9 (4) | 2.1 s |
| **sam3_32b** | 0.00 | 0.00 | −0.36 | 0.38 | 4 (0) | 3.7 s |

走向地标目标的 Δdtg：8B 变近/变远 35%/55% → 46%/43%（n=54）；32B 42%/41% → 43%/45%（n=42）。

诊断：
- 检测命中只占 7–11% 的步；preview 扫视命中 22/255（8B）、5/167（32B）；消歧从未触发。
- 阶段名词短语（正则）质量差：`with bed`、`set`、`backside`、`bottom`、`long hallway next` 之类占了大量步；`french doors`、`large door` 这类合理短语在真实轨迹上命中 0%（基准是在参考路径上采样，地标就在附近；真实轨迹早已偏离）。
- 每步耗时翻倍（每步 1–6 次 SAM3 调用 + 更多 preview 渲染）。

结论：把 grounding 外包给 SAM3、其余不变，在 40 集上没有收益（8B 持平、32B 变差）。要继续的话必须先解决"检测什么"（由 planner 生成检测提示、只对具体物体用检测器）和 preview 触发过频，否则不值得再跑。

## 13. 阶段类型审计与统一分类器（2026-08-31）

## 15. 楼梯模式尝试：负结果，已回退（2026-08-31）

## §19 Phase 0:CWP waypoint predictor 移植 + 候选覆盖率基准(2026-09-01)

### §19.1 设计决定:全景是动作,不是传感器
SmartWay 的"全景相机"在仿真里就是同位置渲染 12 个朝向,物理上等价于原地转一圈
——真机可行(CoW/VLMaps 均如此)。因此我们不照抄"每步全景"(SmartWay 模式),
而是把**环视作为有成本的动作**:默认单目前视,由触发策略决定何时转圈环视。
差异化定位 = 代价感知的主动感知(cost-aware active perception)。

相关工作定位:Active VLN (ECCV'20) 唯一正面做 when/where-to-explore,但是离散
R2R + RL 小模型;MonoDream (2025) 单目但从不环视(latent panoramic dreaming);
AdaNav (2025) 用 action entropy 触发的是推理深度而非观测;Ask When It Pays
(2026) 的成本加权 SR 指标框架可以直接搬。"物理环视作为付费动作 + VLM agent 决策
+ 预测器熵触发"在 VLN-CE 未见先例。

### §19.2 移植细节(integrations/v3/waypoint_cwp/)
- 权重:SmartWay `final-camera-ready`(334MB,增强版 CWP);RGB 编码 DINOv2
  ViT-S/14-reg(冻结,384 维);depth 编码 DDPPO ResNet50 gibson-2plus。
  全部本机缓存,load strict(missing=0/unexpected=0)。
- 输入:12 槽顺时针环(槽 i = 右转 30i°),RGB 224² pitch0 + depth 256²
  归一化 [0,1]@10m;输出 120 角×12 距热力图 → NMS(σ=7,5) → ≤5 waypoint
  (0.25–3.0m)。warm 56ms/次(A100)。
- 兼容:dinov2 hub 仓库 vendor 进 repo 并打 `from __future__ import
  annotations` 补丁(py3.9);BertConfig 用 vendored modeling_bert 重导出;
  file_utils 的 boto3/requests import 改为可选;跑在 runner 侧 habitat env
  (torch 2.8+cu128),与渲染同进程。
- 行为自检:随机噪声输入 → 角度熵 4.787 ≈ ln(120) 理论最大(不确定性信号
  正确);真实场景(ep31)5/5 waypoint 落 navmesh(snap 误差 0.00m)。

### §19.3 覆盖率基准协议
沿 200 集 reference path 以 2m 间距取决策点,agent 朝向=来路方向(不泄漏
GT 转向)。GT=指向下一个 densified 路径点。四路候选源:
① ring:当前位姿全环 CWP(环视上界)② fo:现部署 floor-openings(单目
pitch−15)③ stale:上一决策点旧环对齐当前朝向+新前视槽 0 ④ front45:GT 方向
在前 ±45° 内的比例(一切单目方法的天花板)。命中=±30° 内有候选。
按直行/转向分桶,同时记录 CWP 角度熵与 top-1(环视触发信号验证)。

### §19.4 结果(587 决策点 / 200 集,±30° 命中率)
| 源 | 全部 | 直行(52%) | 转向(48%) | 转向>60° | 背后>120° |
|---|---|---|---|---|---|
| ring 全环 CWP | 96% | 98% | 95% | 93% | 93% |
| stale 旧环+新前视 | 80% | 92% | 52% | 44% | – |
| fo 现部署单目 | 62% | 93% | 28% | 7% | 0% |
| front45 单目天花板 | 58% | 100% | 13% | 0% | 0% |

中位角度误差:ring 4.7° / fo 9.8°(转向点 54.4°)。分类别 ring 均 ≥93%。

### §19.5 结论与决定
1. CWP 移植成功且质量极高,作为环视候选源定案。
2. 87% 转向点 GT 方向不在前扇区 → 环视在转向时刻是必需品;任何单目方法
   (含蒸馏单目头)无法覆盖 → **不训单目候选头**。直行点现有 fo 已 93%≈ring,
   单目步保留现有候选即可。
3. **负结果:CWP 热力图熵不能做环视触发**(转向 4.456 vs 直行 4.447,无分离;
   top1 均值 0.059,近均匀)。原因:CWP 预测几何可走性,转向是指令语义事件。
   触发信号改用指令/进度侧:turn-stage、子目标切换、前方无匹配候选、看门狗。
4. Phase 1:pano-hop agent,决策点四条件任一命中即环视(否则单目 fo 候选),
   对照上界=每步环视、下界=从不环视。

## §20 Phase 1:pano-hop actor(2026-09-01)

### §20.1 机制(integrations/v3/panohop_actor.py,commit 92ad75f)

  attach_env;执行环路零改动。
